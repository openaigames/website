# Site analytics

Administrators open `/admin#analytics` and sign in with GitHub. The existing immutable administrator-ID check protects `GET /api/admin/analytics`; ordinary signed-in users cannot read reports. English and Chinese views offer today, seven days, thirty days, or a custom range within the most recent 90 Shanghai calendar days.

## Definitions

- Page views (PV): one event for each visible top-level homepage document load. Room panels, language changes and hash routes do not create additional page views. Browser back/forward-cache restoration does not reload the document or create another PV.
- Visitors (UV): distinct anonymous browser identifiers within the selected range, not the sum of daily UV. Browser storage lasts 90 days. Different browsers, cleared storage and different origins can count the same person separately. This is not an exact people count.
- Game selections: explicit 3D cartridge picks, screen choices (including keyboard/controller navigation), and catalog/detail clicks. Hover, the initial default selection, language changes and opening feedback do not count. Choosing the same game again is another intentional selection. Viewing a catalog detail and then inserting its cartridge are two actions; direct game links may skip selection. Do not divide opens by selections and label it a conversion rate.
- Game opens: creating the playable game iframe, including restarts and direct game links. Returning from an overlay to the same iframe does not count again. Opening an iframe does not prove that an external game loaded or that a round was played.
- Players: distinct anonymous identifiers with a game-open event in the selected range. Game identity hashes the play URL, matching feedback identity and surviving promotion from intake to formal catalog.
- Website active time: foreground, focused parent-page time, sampled every 5 seconds and cumulatively saved every 30 seconds plus best-effort blur/hide/exit saves. Pauses after 60 seconds without parent-page input and while the embedded game has focus; gaps over 10 seconds are discarded to avoid counting suspended devices. Input events only renew an activity timestamp: no keys, pointer coordinates or input contents are transmitted. Cross-origin game actions are not observable, so this is **not actual gameplay time**.
- Timed visits: pageview v2 documents that entered during the selected dates, including visits with zero recorded active time. Total/average active time use this cohort and exclude older pageviews that never supported timing. A cross-midnight visit belongs to its entry date; late heartbeats can update that cohort. Each document is capped at 24 hours of cumulative active time. Empty timing cohorts display “—”.
- Community activity: submissions, currently visible comments and notes created within the chosen dates. Likes and active ratings are labeled as current totals because their existing rows represent current choices, not historical actions.
- Sources: allowlisted `utm_source` categories or a coarse category inferred from the referrer host. Unknown or missing referrers cannot be reconstructed. WeChat and Xiaohongshu links are available to copy in the dashboard. No raw referrer or arbitrary query values are submitted.

Reports fill empty dates with zero. `engagementStartedAt` marks the first timing-capable visit; old durations and selections are not backfilled. `startedAt` is the first accepted event; visits before enabling collection cannot be recovered. Source/device/domain UV can overlap and must not be added to obtain overall UV. Known crawlers, DNT/GPC opt-outs, network failures and blockers affect collection; these are approximate browser metrics, not an audited traffic or billing counter.

## Data and endpoints

`POST /api/analytics/event` accepts only a UUID event ID, UUID browser ID, `pageview`, `play`, `select` or `engagement`, a bounded source category and a coarse device category. Game events require a published game ID. Pageviews optionally declare `version: 2`; only those create timing-enabled visit rows. Heartbeats require a known visit UUID and a nonnegative integer `activeMs` no greater than 24 hours or server-observed elapsed time plus 10 seconds. The visit must match both the salted browser identity and entry hostname. The server controls timestamps and game titles; unapproved games are rejected. Event IDs make event retries idempotent. Heartbeats update a per-visit cumulative maximum, making retries and out-of-order requests safe without storing every interval. The client waits for pageview acceptance before sending heartbeats. A per-minute hashed-address quota limits event spam, including clients rotating browser IDs.

Only the server's salted digest of the anonymous browser ID is stored. No raw IP, complete user agent, browser fingerprint, full referrer, account identity or free-form event properties are stored. Address-quota keys include a minute boundary and the server secret, and cannot be used as report visitor IDs. Counts are kept separately from GitHub accounts.

The main site posts to its own endpoint. The legacy Workers domain posts anonymous events directly to the same canonical endpoint using restricted CORS and `credentials: omit`; it continues to share the primary database. The legacy gateway and its narrow write-route list are unchanged. Preview and unconfigured environments reject collection. Local development stores only local events.

`ANALYTICS_ENABLED=1` and the existing server session secret enable collection. `0005_icy_famine.sql` adds `analytics_events`, `analytics_limits` and `analytics_meta`; no existing table is changed. `0006_steady_zaran.sql` adds the indexed `analytics_visits` table; the event table remains compatible with older clients. A daily 19:15 UTC / 03:15 Shanghai cron deletes events and timed visits older than the available 90-day calendar window and expired quota records. The first-event timestamp remains. Disabling collection stops new events; remove old records separately if retention should end as well.

For a verification visit that should not count, add `?analytics=off`. This is a local browser opt-out, not an authorization mechanism. Tests use isolated databases and never add synthetic traffic to production.

## Validation

The 72-test suite covers authentication, cross-origin collection, input validation, anonymous-ID hashing, retry deduplication, range UV, Shanghai day boundaries, published-game validation, promotion identity, retention, disabled previews, client visibility and privacy opt-outs, cumulative and out-of-order duration updates, foreign-visit rejection, old-client denominator exclusion, idle/hidden/iframe-focus pauses, device suspension, exit saves and BFCache restoration. An isolated browser fixture checks populated reports, date filters, language switching, 320/390 px layouts, and an actual homepage/game-open sequence. Opening and closing the review panel leaves both PV and game-open counts unchanged.
